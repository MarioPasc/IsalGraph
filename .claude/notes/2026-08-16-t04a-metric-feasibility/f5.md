## 1. What I changed, file by file

### `src/isalgraph/competitors/bootstrap.py` (new)

Graph-level percentile bootstrap. Three decisions worth naming:

- **`make_resample_index(n_graphs, *, resamples, seed)` is separate from
  `graph_bootstrap_ci(x, y, pair_index, index, *, alpha, min_pairs)`.** The brief allowed an
  "equivalent signature you document": this is it. Splitting them is what makes D7 enforceable —
  the caller builds one `ResampleIndex` per (dataset, view) and hands the *same object* to every
  representation, so their intervals are paired rather than independently noisy. A test asserts
  the object identity is shared, by spying on `f5.graph_bootstrap_ci`.
- **`random.Random(seed)`, not `numpy.random.default_rng`.** CONTRACTS §5 names `random.Random(42)`
  explicitly; the brief permitted either. I took the contract's, so there is no discrepancy to
  reconcile later. Determinism is asserted.
- **Self-pairs are dropped by construction.** A replicate draws graphs with replacement, so one
  graph can occupy two slots. Pairing it with itself would add a distance-0/GED-0 point that was
  never observed, biasing rho upward exactly where the distribution is tightest. The pair lookup
  table's diagonal is never written, so a duplicated slot resolves to "absent" rather than to a
  fabricated zero. Tested with `n_graphs=2`.
- `None` is returned rather than a fabricated interval when fewer than two replicates produce a
  defined rho (each replicate needs ≥ 3 surviving pairs).
- Inner rho is `rankdata` + Pearson rather than `scipy.stats.spearmanr`: the p-value scipy computes
  on every replicate is never read and dominated the cost. Same statistic. The **point estimate**
  still goes through `spearmanr`, so the reported `p` is scipy's.

### `src/isalgraph/competitors/ged_reference.py` (additive only)

`load_ged` is untouched — `reproduce.py` keeps working unchanged. Added `GEDBounds`,
`load_bounds(dataset, which)`, `BOUNDS_SUBDIR/BOUNDS_DIR/BOUNDS_KEY`, `MAX_OFFDIAG_ZERO_FRACTION`.

- `graph_ids` alignment against the cohort is **asserted**, as `load_ged` does.
- `GEDBounds.finite_pairs` filters with `np.isfinite`. A GED of exactly 0 is kept.
- Matrix-level guards at load: any negative finite entry aborts; an off-diagonal exact-zero fraction
  ≥ 0.99 aborts. That is the shape of GEDLIB's silent wrong-accessor failure. There is **no**
  per-pair `value > 0` rule.
- `load_bounds(ds, "mid")` raises. There is no third side of the bracket.

### `src/isalgraph/competitors/f5.py` (rewritten)

New CLI: `--grid --out --resamples --seed`, **plus `--n-graphs` and `--datasets`**. `--n-graphs` is
required by acceptance criterion 5 (a 40-graph demonstration run); its default is the frozen 200 and
`--datasets` defaults to every cohort present under the root. The old `--metric` flag is gone.

`grep -rn "competitors.f5\|competitors import f5" src/ tests/ benchmarks/ experiments/` finds **no
programmatic caller** — only prose in `__init__.py`/`grid.py`/`README.md` and
`tests/unit/test_competitors_core.py::test_f5_is_the_only_entry_point_that_can_see_ged`, which
asserts the import closure and still passes. Nothing broke.

Each representation runs under its own `primary_distance` from the grid. Both views, the size null in
every view, `n_unencodable` reported per backend, `::lb` and `::ub` as two records that are never
averaged. The module docstring still states F5 is descriptive and is not an input to selection.

### `tests/unit/test_competitors_f5.py` (new) — 24 tests

Fully synthetic: the fixture writes a six-graph CSR cohort, an exact-GED file and both bound files
under a temporary `ISALGRAPH_COHORT_ROOT`, then clears the `functools.cache`s. One test is marked
`integration` and skips when the external drive is unmounted.

## 3. Things in the brief that turned out to be wrong or incomplete

Reporting these plainly, as instructed. Items 1 and 2 changed the code's behaviour.

### 3.1 The Suite-2 arm **cannot** report `isalgraph_canonical` — the question as posed is unanswerable

The brief's stated open question is "whether IsalGraph clears the size null anywhere in Suite 2".
`isalgraph_canonical` declares `Capability.SUITE1_ONLY` and raises `SuiteScopeError` above n = 12.
Measured on the 40-graph GREC draw: **11 of 40 graphs refused, 406 of 780 pairs surviving** — and
the 374 lost pairs are precisely the hardest ones. `base.table_scope_error` is the frozen rule for
this (design criteria 5 and 9): a backend may be *run* on Suite 2 to measure its ceiling, but it may
not contribute a *printed row* there, because the row would be conditioned on the graphs that
happened to finish.

I applied that rule. `agm_cam` and `isalgraph_canonical` are emitted on every Suite-2 record as a
printed absence carrying `table_scope_error`'s reason, and are not encoded at all there.
**IsalGraph is represented in Suite 2 by `isalgraph_pruned` only**, which is not `SUITE1_ONLY` and
encoded all 40 GREC graphs. If the intent was to report the canonical variant's Suite-2 rho anyway,
that is a decision to overrule a frozen criterion and it is yours, not mine — tell me and I will
add it behind an explicit flag.

### 3.2 The size null is **undefined by construction** in the equal-`n` view, and NaN is not JSON

`rho(|n₁ − n₂|, GED)` on a view where `n₁ == n₂` correlates a constant column. `scipy` returns
`NaN` and warns; it does not raise. `json.dump` then writes the bare token `NaN`, which is not valid
JSON (RFC 8259) and which a strict downstream parser reads as either a failure far from the cause or
as a number.

Fixed two ways: any constant column now produces a printed absence with a stated reason
(`"Spearman undefined: the 'size_null' distance is constant over the pairs of this view..."`), and
the writer passes `allow_nan=False` so anything I missed aborts at the write rather than downstream.

**Track C must handle `size_null.rho is None` in the `equal_n` view.** It happens on every dataset,
in every run. This is not an edge case; it is the definition of the view.

### 3.3 CONTRACTS §5 — three additions, all supersets, none renaming a frozen field

Flagging rather than assuming. Nothing in §5 was removed or renamed.

1. **Every cell carries the same eight keys**, `size_null` included:
   `metric, rho, p, ci, n_pairs, n_undefined, zero_frac, reason`. §5 shows `size_null` with four.
   The superset lets track C index one shape.
2. **`n_unencodable[<backend>]` can be `null`**, not only an int — for a representation that was
   never attempted (no admissible distance, or refused by §3.1). `0` there would assert that every
   graph encoded, which is false.
3. **Extra keys**: `wall_seconds` (top level), `n_reference_pairs` and `encode_errors` (per record).
   `encode_errors` maps backend → `{ExceptionName: count}`.

Also added, and not in §5: a representation present in `available_backends()` but **absent** from
the grid's `primary_distance` map is emitted with `reason = "absent from the grid's
primary_distance map"` rather than dropped, so a silently shrinking grid cannot silently shrink the
F5 table. It is told apart from `"no admissible distance (T-04a selection)"`.

### 3.4 The censoring trap is real but currently inert on these five cohorts

The brief warns that censored values are `inf`. Verified across all five Suite-2 datasets
(`grec`, `aids_iam`, `coil_del`, `mutagenicity`, `protein`), both `LB` and `UB`:
**zero non-finite entries and zero negative entries**. `grec`'s metadata reports
`censoring_rate: 0.0`. The `np.isfinite` filter is kept regardless — it costs nothing and the
`UB_TIGHT`/`UB_SENSITIVITY` trees are not guaranteed to share that property.

### 3.5 `graph_ids` alignment — verified on all five, not just `mutagenicity`

The brief verified `mutagenicity` (4,040). I checked all five Suite-2 cohorts against **both** the
`LB` and the `UB` file: `grec` 650, `aids_iam` 1,811, `coil_del` 3,900, `mutagenicity` 4,040,
`protein` 569 — exact match in every case. Asserted in code anyway.

### 3.6 `LB/<ds>.npz` and `UB/<ds>.npz` each carry **both** `lb_matrix` and `ub_matrix`

Reading the wrong key from the right file is therefore silent. The loader hard-codes
`BOUNDS_DIR[which]` and `BOUNDS_KEY[which]` together so the pair cannot come apart, and a test
asserts `lb.values != ub.values` and `lb <= ub` elementwise.

### 3.7 `aids_graphedx` — confirmed not needed

It exists under `APPROX_GED/{LB,UB}/` but is not in `datasets.ALL_DATASETS`, so `load_bounds` on it
raises `DatasetNotFoundError` through `suite_of` before any positional join can happen. Suite-1
`aids` (769) has **no** LB/UB file at all, which is consistent: Suite 1 uses certified exact GED.

## 6. Two defects the demonstration runs missed and the full protocol found

### 6.1 `encode_draw` caught `CompetitorError`, which is the wrong branch — `934a8f1`

The full protocol crashed and wrote nothing:

```
f5.py:146   encoded[idx] = backend.encode(graph)
  -> backends/isalgraph_ref.py:155 -> core/backends.py:358
  -> isalgraph.errors.CanonicalizationTimeoutError
```

The hierarchy has two branches under one root, and I guarded only one:

```
IsalGraphError
├── CompetitorError      AGMBudgetExceeded, MinDfsBudgetExceeded, SuiteScopeError, BudgetExceeded
└── EncodingError
    └── CanonicalizationTimeoutError      <- the core engine's wall clock, NOT a CompetitorError
```

`isalgraph_ref` lets the core engine's timeout propagate unchanged, so my guard caught every
*competitor backend's own* cap and missed the *engine's*. CONTRACTS §5 and my brief both required
an unencodable graph to be counted and excluded; `grid.py` had already hit the identical situation
and caught broadly. **The catch is now `IsalGraphError`** — the common base, still narrow enough
that a `TypeError` in our own code propagates. Kinds stay counted under their own names, never
summed, for T-06's `error_kind` column.

I also found and guarded a second instance of the same shape: `VectorBackend.fit()` is called
**outside** the per-graph loop and so was outside the per-graph guard. A raise there would have
taken the run down for one representation. It is now a reported total failure for that backend.

Two regression tests, both **verified to fail against the old catch** before being kept.

### 6.2 The grid's `size_null: null` entry deleted the null row — `66d7dbe`

Found while inspecting track A's real `grid_200.json` before re-running. It lists

```json
"size_null": null
```

correctly — CONTRACTS §4 forbids selecting a baseline as any representation's primary distance. But
`size_null` is *also* the dedicated baseline row every other row is judged against. My
`dataset_record` wrote the null row, then fell through to the representation loop, hit `size_null`
with a `None` distance, and **overwrote the null row with a printed absence**. The entire F5 table
would have shipped with no size null in any view of any dataset — the one column the whole arm
exists to print — and nothing would have raised, because a printed absence is a legitimate value
everywhere else.

The baseline is now emitted once, before the loop, and the loop skips it. Test added on a grid
shaped like the real one.

### 6.3 What this says about the verification, plainly

Both defects were reachable only through inputs my demonstration runs did not have:

- **§6.1 needed large graphs.** The canonicalisation budget is 2.0 s; 40 Letter or GREC graphs never
  approach it. A demo on small graphs is not coverage of the failure path — it is coverage of the
  path where the failure does not occur.
- **§6.2 needed the real grid.** I hand-wrote the fixture grid per the brief and omitted a key I did
  not know would be there. A fixture written by the consumer cannot test the producer's schema.

Both are now covered by unit tests that construct the triggering input directly, which is the only
form of coverage that does not depend on a cohort being mounted or a graph being large enough.

Three findings, none of which flatters us, and all of which are F5 — descriptive, and no input to
selection.

1. **The Suite-1 result reproduces the brief exactly: 1 of 5, and the interval swallows it.** On
   `iam_letter_low` the +0.036 margin has overlapping intervals, so it is not a separation. On the
   other four IsalGraph is below the null, three of them with disjoint intervals. **A reviewer who
   computes the size null on Suite 1 has a real objection and we cannot answer it with rho.**
2. **The `lb` arm is a size proxy across the whole cohort, not just GREC.** The size null scores
   0.960–0.998 against BRANCH_FAST on all five Suite-2 datasets and beats every representation on
   every one, with disjoint intervals throughout. BRANCH_FAST's bound is close to a monotone
   function of the node-count difference. **The `lb` arm cannot support any claim about structure**,
   and averaging it with `ub` would have produced a midpoint with no interpretation. This is the
   measured justification for the no-interpolation rule.
3. **Against `ub`, IsalGraph clears the null on all five Suite-2 datasets — and is never the best
   representation on any of the 15 records.** Counting the top representation per all-pairs record:
   `min_dfs` 4, `agm_cam` 3, `wl_subtree` 3, `sparse6_nauty` 3, `nauty_graph6` 2, **IsalGraph 0**.
   `min_dfs` beats IsalGraph on four of five Suite-1 datasets. F5 does not select anything, so this
   changes no decision — but it is the number a reviewer will compute, and the manuscript should say
   it before they do.
